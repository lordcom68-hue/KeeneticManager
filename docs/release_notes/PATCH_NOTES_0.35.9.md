# Keenetic Manager 0.35.9 — стабильная версия разработки

- Статус версии: `stable` в канале `development`. Это стабильная контрольная
  точка текущей разработки, а не финальный релиз продукта.

- Исправлена синхронизация сохранённого MWS, runtime MWS и физических
  AccessPoint-интерфейсов при включении и выключении Wi-Fi.
- Неизвестное состояние интерфейса отделено от подтверждённого состояния
  «выключен».
- Проверка переключения сохраняет исходный список AccessPoint и не теряет его,
  если профиль исчезает из runtime после выключения.
- Для включения требуется подтверждение всех физических AccessPoint сети.
- Учтено поведение KeeneticOS 5.01: `show/mws/wlan.band.enabled` может хранить
  предыдущее значение после успешного переключения. При известных AccessPoint
  это поле остаётся диагностическим и не вызывает ложную ошибку.
- Отсутствующий `enable` в `show/sc/mws/wlan` после команды выключения
  корректно распознаётся как сохранённое выключенное состояние.
- При переименовании сети сохраняется состояние каждой физической точки
  доступа. После изменения MWS приложение явно повторяет `up` или `no up`,
  поэтому обновление имени больше не выключает диапазоны 2,4 и 5 ГГц.
- Состояние сохраняется для точек всех MWS-профилей: переименование второй
  сети больше не выключает первую сеть из-за общего перезапуска Wi-Fi
  конфигурации KeeneticOS.
- Успешное изменение имени теперь подтверждает не только новый SSID, но и
  исходное физическое состояние всех затронутых AccessPoint, включая соседние
  сети; при ошибке оно также восстанавливается во время отката.
- Диагностика записывает событие `wifi_mws_update` со списком сохранённых
  интерфейсов и результатом проверки переименования.
- Неподтверждённое состояние возвращается как ошибка с диагностикой вместо
  ложного сообщения «Готово».
- Добавлены регрессионные тесты пустого runtime, исчезновения MWS-профиля,
  частично переключившихся диапазонов, сброса AccessPoint при переименовании и
  выключения первой сети при изменении второй.
- При возврате диапазона MWS собственная устаревшая runtime-привязка больше не
  считается другой сетью с тем же SSID.
- Для профиля без диапазона вместо неактивной кнопки показывается действие
  «Назначить диапазон», открывающее редактирование сети.
- Для KeeneticOS 4 добавлен отдельный legacy-режим физических AccessPoint:
  создание, изменение, включение, выключение и удаление дополнительных сетей,
  сохранение привязки к Bridge и синхронизация 5 ГГц через `follow access-point`.
- Legacy-режим включается только для KeeneticOS 4. На KeeneticOS 5 без MWS API
  потенциально несовместимые физические команды остаются заблокированными.
- Любая legacy-операция проверяет фактическое состояние интерфейсов и пытается
  восстановить исходную конфигурацию при ошибке.
- Исправлён возврат диапазона профилю, сохранённому без `band` и без явного
  `enable`: приложение передаёт состояние сети явно и не включает её скрыто.
- Проверка назначения диапазона учитывает физическое состояние AccessPoint,
  если KeeneticOS не сохраняет `enable=false` или оставляет устаревший MWS
  runtime-флаг.
- Откат профиля без диапазонов больше не требует несуществующей привязки к
  AccessPoint и корректно подтверждает восстановленное имя и состояние.
- Кнопка «Удалить» постоянно отображается на карточках вкладки Wi-Fi. Для
  защищённых системных сетей она остаётся неактивной и показывает причину в
  подсказке. В карточках мониторинга кнопка удаления скрыта.
- Исправлено удаление MWS-сетей: назначенный KeeneticOS номер AccessPoint
  больше не делает пользовательский профиль системным, а профиль без
  диапазонов удаляется по своему MWS ID без физического интерфейса.
- Устранены фантомные Wi-Fi сети после удаления: при доступном MWS API пустой
  список профилей означает отсутствие сетей, а несвязанные физические SSID и
  их устаревшие карточки удаляются из кэша.
- Исправлено определение типа клиентов на KeeneticOS 5.00: устройства,
  переданные роутером только во вложенном блоке `mws`, теперь отображаются как
  Wi-Fi-клиенты с правильным диапазоном, а не как проводные устройства.
- Для проводных клиентов поле `via` с MAC-адресом больше не принимается за
  Ethernet-интерфейс. Внешний номер порта сопоставляется с физическим
  `GigabitEthernet`/`FastEthernet` интерфейсом на разных моделях роутеров.
- Скорость Ethernet-подключения нормализуется с учётом единиц измерения и
  показывается в обоих направлениях как согласованная скорость порта; также
  отображаются номер порта и дуплекс.
- Если версия KeeneticOS не возвращает обратную PHY-скорость Wi-Fi, карточка
  явно показывает «нет данных» и поясняет причину в подсказке вместо
  неоднозначного прочерка.
- В меню создания подключений убрано неработающее VPN-подменю. Пункт «Другие
  подключения» теперь открывает информационное сообщение так же, как пункт
  «Мобильное подключение».
- Неактивные кнопки «Удалить» скрыты возле VPN-подключений. Поддерживаемые
  рабочие действия удаления и кнопки других типов подключений не затронуты.
- Системные эмодзи статуса в списке роутеров заменены плоскими индикаторами,
  отрисованными приложением: мятный — доступен, мягкий красный — недоступен,
  янтарный — проверяется, серый с контуром — статус неизвестен.
- Индикатор доступного роутера получил тонкое полупрозрачное внешнее кольцо;
  размер точек и отступ перед названием теперь одинаковы на всех системах.
- Шеститочечные ручки списка роутеров заменены спокойными капсулами с тремя
  горизонтальными штрихами. При наведении появляется мягкий фон и курсор-
  ладонь, при захвате — синий акцент и закрытая ладонь.
- Индикатор места вставки при перестановке стал тоньше и использует единый
  синий акцент списка.
- Перетаскиваемая строка роутера теперь следует за курсором отдельной
  полупрозрачной карточкой, а исходная строка мягко приглушается до завершения
  операции.
- Линия места вставки плавно перемещается между строками. Автопрокрутка у
  верхнего и нижнего края переведена на непрерывное попиксельное движение с
  ограничением скорости.
- Безопасная логика перестановки сохранена: список и база изменяются ровно
  один раз после отпускания мыши, отмена клавишей Escape ничего не сохраняет.
- Панель действий роутеров разделена по назначению: глобальные «Обновить все»
  и «Добавить» перенесены в заголовок, а подключение выбранного роутера
  отображается компактным статусом с одной актуальной кнопкой.
- Состояния подключения, повторной попытки, нестабильной связи и остановки
  больше не маскируются под неактивную кнопку «Подключён» и сохраняются при
  переключении между роутерами.
- «Изменить» и «Удалить» заранее блокируются на время работы и завершения
  мониторинга с поясняющей подсказкой. Удаление получает красный акцент только
  при наведении.
- Повторное подключение невозможно, пока предыдущий поток мониторинга ещё
  завершает сетевой запрос.
- Общая схема физических портов стала крупнее и проще: Ethernet и USB теперь
  используют единый размер, состояние, подписи и эффект наведения.
- Подключённые порты выделяются мятным индикатором и мягким голубым контуром,
  отключённые и выключенные — приглушённым серым. Роль WAN вынесена в
  небольшую плашку и больше не перекрывает изображение разъёма.
- Скорость показывается локализованно (`1 Гбит/с`, `100 Мбит/с`), а дуплекс
  убран со схемы и доступен в подробной подсказке порта.
- CPU и память перенесены в карточку «Устройство» и оформлены компактными
  системными метриками справа от модели, версии KeeneticOS и времени работы.
- Проценты, обновление значений, очистка при отключении и подробные подсказки
  сохранены. Для быстрого различения CPU использует мятный, а память —
  голубой тонкий индикатор.
- Отдельный ряд крупных карточек CPU и памяти удалён, поэтому мониторинг
  занимает меньше высоты без потери данных.
- Автообновление полных данных и проверка доступности роутеров разделены на
  два независимых переключателя. Выключенная проверка показывает нейтральный
  статус вместо бесконечного состояния «проверяется».
- Состояния обоих переключателей и выбранный интервал сохраняются между
  запусками приложения.
- Подключение роутера больше не включает автообновление вопреки выбору
  пользователя: начальный снимок выполняется один раз, затем монитор соблюдает
  сохранённое состояние паузы.
- Устранена гонка события пробуждения, которая могла запускать два цикла сразу
  после подключения или снятия паузы. Запросы по-прежнему выполняются строго
  последовательно и объединяются.
- Убрано повторяющееся сообщение «Данные роутера обновлены» после каждого
  фонового цикла.
- Закрытие приложения теперь неблокирующее: окно скрывается сразу, но процесс
  безопасно дожидается всех активных и уже завершающихся сетевых потоков,
  прежде чем уничтожать Qt-объекты.
- В верхнюю панель роутера добавлены два режима: «Спасатель» выключает
  настроенный Wireless ISP и включает раздаваемые Wi-Fi сети с назначенными
  диапазонами; «Спасаемый» включает Wireless ISP и выключает раздачу Wi-Fi.
- Переключение выполняется одной последовательной операцией в потоке роутера.
  Если следующий шаг не подтверждён, приложение пытается восстановить
  исходные состояния WISP и Wi-Fi в обратном порядке.
- Индикатор различает подтверждённые режимы «Спасатель» и «Спасаемый», а также
  честно показывает переходные состояния «Смешанный», «Оба выключены» и
  недоступность функции при отсутствии WISP или сети с диапазоном.
- WISP определяется только по настроенному WifiStation, а раздаваемые сети —
  только по MWS/legacy-профилям с физическими AccessPoint. Проводные и
  созданные без диапазона сети в переключение не попадают.
- Устранено мерцание при переходе между двумя подключёнными роутерами:
  рабочие вкладки больше не заменяются на мгновение офлайн-страницами, а
  сохранённый снимок следующего роутера обновляет существующие карточки на
  месте. При выборе отключённого роутера полная очистка по-прежнему работает.
- Зафиксирован протокол подключения по типу адреса: локальные IP используются
  только через HTTP, а KeenDNS — только через HTTPS. Убрана предварительная
  локальная HTTPS-попытка, из-за которой `192.168.3.1` каждый раз ожидал
  восьмисекундный тайм-аут перед успешным HTTP-подключением.
- Диагностический архив теперь содержит отдельное событие
  `rescue_mode_switch` для всей операции «Спасатель/Спасаемый»: запрошенный и
  исходный режимы, безопасные идентификаторы WISP и Wi-Fi, запланированные и
  выполненные шаги, общий результат, а при ошибке — факт и итог отката.
- Отказ предварительной проверки режима также журналируется. Сбой самой
  диагностики изолирован и не может прервать переключение роутера.
- Схема базы данных остаётся 280.
