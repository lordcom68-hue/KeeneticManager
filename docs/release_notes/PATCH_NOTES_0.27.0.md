# Keenetic Manager 0.27.0 — тестовая сборка

## Главное изменение

Пароли администраторов роутеров больше не хранятся открытым текстом в
`database/routers.db`. При миграции 0.27.0 приложение переносит их в
Windows Credential Manager через пакет `keyring`.

## Что произойдёт при миграции рабочей базы

1. Для каждого непустого старого пароля создаётся случайная ссылка.
2. Пароль записывается в Windows Credential Manager.
3. В SQLite остаётся только `credential_ref`.
4. Колонка `password` удаляется перестроением таблицы.
5. Выполняется `VACUUM`, чтобы старые байты секрета не оставались
   в свободных страницах SQLite.
6. Старые `routers_backup_*.db` очищаются от открытых паролей.

При ошибке Credential Manager активная SQLite-база откатывается без
частичной миграции, а уже созданные тестом секреты удаляются.

## Поведение окна редактирования

Сохранённый пароль никогда не подставляется обратно в GUI.

- пустое поле — сохранить текущий пароль;
- новое значение — заменить пароль;
- «Удалить сохранённый пароль» — удалить секрет;
- явное удаление возвращает `password=None`, а не пустую строку.

## Исправления после первой Windows-проверки

- все SQLite-соединения теперь закрываются явно в `finally`;
- устранена блокировка временных `routers.db` на Windows;
- добавлен тест, который считает открытые и закрытые соединения;
- исправлена семантика удаления пароля в `AddRouterDialog`;
- тестовая сборка не устанавливается в рабочий проект и не запускает
  миграцию пользовательской базы.

## Порядок выпуска

1. Запустить отдельную Windows-проверку этой тестовой сборки.
2. Убедиться, что unit-тесты и временный Credential Manager smoke-тест
   прошли полностью.
3. Только после успешного отчёта подготовить обновление рабочей 0.26.6.

## Безопасность тестовой сборки

Архив не содержит пользовательские:

- `database/routers.db`;
- `routers_backup_*.db`;
- `diagnostics_history`;
- `logs`;
- пароли;
- диагностические ZIP;
- `__pycache__`, `.pyc` или `.pyo`.
