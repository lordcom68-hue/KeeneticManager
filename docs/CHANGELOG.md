## 1.0.14-rc1 — первый релиз-кандидат

- Заморожен набор функций `1.0.14`; до стабильного выпуска
  принимаются только исправления дефектов.
- Ручная диагностика на Keenetic Sprinter KN-3711 с KeeneticOS 5.1.1
  подтвердила Wi-Fi MWS, Dedicated WAN, режимы
  «Спасатель»/«Смешанный» и восстановление локальной HTTP-сессии.
- Профиль хранения оставлен в канале `beta`, поэтому база,
  настройки и учётные данные предыдущей beta-версии сохраняются.

## 1.0.14-beta — устойчивое переключение режимов

- Добавлен режим «Смешанный», одновременно включающий Wireless ISP и
  раздачу Wi-Fi без изменения существующих режимов «Спасатель» и
  «Спасаемый».
- Переключение, отключающее текущий канал управления, теперь выполняет
  контролируемую передачу сессии: локальная сеть → KeenDNS или
  KeenDNS → локальный адрес.
- Управляющие команды не выполняются без активной сессии, а ожидают
  переподключения; офлайн-создание диагностического архива сохранено.
- Исправлено зависание состояния «Остановка мониторинга…», закрытие активной
  HTTP-сессии и автоматическое продолжение отложенного подключения.
- Диагностическая очистка расширена для закрытых ключей конфигурации;
  архивы не содержат сохранённых секретов роутера.
- Создание MWS-сетей учитывает фактическую схему KeeneticOS и не отправляет
  неподдерживаемые ветви `mlo`, `band-steering`, `iapp` и другие поля,
  вызывавшие ответ RCI `no input` на KN-3711.
- Открытые MWS-сети используют системное значение KeeneticOS `none`, тогда
  как внутреннее значение интерфейса `open` больше не отправляется в RCI.
- При создании MWS-сети доступны WPA2-PSK, смешанный WPA2/WPA3-PSK,
  WPA3-SAE, OWE и открытый режим; WEP и устаревший WPA не предлагаются.
- Дополнительные режимы защиты нормализуются при чтении и корректно
  отображаются в карточке и диалоге редактирования; legacy-режим ограничен
  WPA2 и открытой сетью.
- Смена безопасности MWS-сети подтверждается повторным чтением профиля;
  неподтверждённое изменение автоматически откатывается.
- При смене защиты приложение отправляет полный сохранённый MWS-профиль и
  не дублирует команды на физических точках доступа, поэтому переходы в
  WPA3, OWE и открытый режим не отменяются фоновой синхронизацией MWS.
- Для перехода существующей сети в открытый режим используются штатные
  маркеры KeeneticOS удаления `encryption` и `wpa psk`, а не принимаемое
  только при создании значение `none`.
- Системный MWS-профиль `DEFAULT__` теперь, как и в штатном интерфейсе
  Keenetic, позволяет менять диапазоны и удалять сеть; перед удалением
  показывается отдельное предупреждение о возможной потере Wi-Fi-доступа.
- Полный комплект содержит 726 тестов; Ruff проходит, общее покрытие — 58%.

## 1.0.8-beta — безопасная самопроверка роутера

- В карточке совместимости настроек добавлена фоновая read-only самопроверка,
  не блокирующая интерфейс и не изменяющая конфигурацию KeeneticOS.
- Локальный адрес отдельно проверяется по HTTP, а KeenDNS — по HTTPS; для

- Контрольный полный снимок проверяет системные данные, Интернет, клиентов,
  Wi-Fi, физические порты, профиль совместимости и системный журнал.

- Отчёт можно скопировать или сохранить в JSON; адреса, имя роутера, пароль и
  другие учётные данные в него не включаются.
- Последняя обезличенная сводка сохраняется отдельно для каждого роутера,

- Пробные сессии не меняют основное подключение и не записываются в историю

## 1.0.5-beta — безопасное управление Ethernet-портами

- Управление физическими Ethernet-портами вынесено в типизированный
  `PortStatusService`, общий для старых и современных KeeneticOS.
- Административное состояние порта теперь определяется отдельно от физического
  линка: вынутый кабель больше не выглядит как выключенный порт.
- Если KeeneticOS возвращает вложенную и полную копии одного порта, для
  подтверждения выбирается запись с административным `summary.layer.conf`;
  сохранённая конфигурация используется только как резервный источник.
- Порт, через который приложение связано с роутером, нельзя случайно
  выключить ни из карточки клиента, ни прямым вызовом совместимого фасада.
- Перед изменением сохраняется подтверждённое исходное состояние; если новое
  состояние не подтверждено, приложение пытается автоматически выполнить и
  проверить откат.
- Кнопки порта блокируются до результата операции, а отдельная кнопка
  восстановления остаётся доступной для выключенного порта без клиента.
- В диагностике сохраняется типизированный итог каждой операции с портом;
  минимальное покрытие проекта повышено до 43%, нового сервиса — до 89%.

## 1.0.3-beta — единая обработка трафика

- Расчёт скоростей интернет-подключений вынесен из `KeeneticClient` в

## 0.35.9 — стабильная версия разработки

- Версия отмечена как `stable` в канале `development`; это стабильная
  контрольная точка разработки, а не финальный релиз.

- Исправлено подтверждение переключения Wi-Fi между сохранённым MWS,
  runtime MWS и физическими AccessPoint-интерфейсами.
- Отсутствующие runtime-данные больше не считаются автоматически состоянием
  «выключено»; для проверки дополнительно используется конфигурация интерфейса.
- Итоговая проверка использует список AccessPoint, сохранённый до переключения,
  и требует ожидаемого физического состояния для всех точек сети.
- На KeeneticOS 5.01 runtime MWS может сохранять предыдущее значение после
  успешного переключения; при известных AccessPoint он используется только
  для диагностики и не создаёт ложную ошибку.
- Исправлено выключение физических AccessPoint после переименования сети:
  транзакция сохраняет и восстанавливает состояние каждого диапазона всех
  MWS-профилей, а затем проверяет одновременно новый SSID и фактическое
  состояние изменяемой и соседних сетей.
- Переименование второй сети больше не выключает первую сеть при общем
  перезапуске беспроводной конфигурации KeeneticOS.
- Откат неудачного редактирования также возвращает исходные `up/no up`.
- В диагностический архив добавляется событие `wifi_mws_update` с результатом
  проверки и сохранёнными состояниями AccessPoint.
- Неподтверждённая команда больше не показывается приложением как успешная.

# Keenetic Manager — история изменений

## 0.27.0

- Пароли администраторов роутеров перенесены из SQLite в Windows Credential Manager через `keyring`.
