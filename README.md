# Keenetic Manager

Настольное приложение для мониторинга и управления роутерами Keenetic.
Текущая версия — `1.0.12-beta`. Это стабильная контрольная точка в ходе
разработки, предназначенная для технической проверки перед следующим выпуском.

## Установка и запуск

Откройте PowerShell и выполните:

```powershell
cd D:\Proekt\KeeneticManager
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python main.py
```

При последующих запусках достаточно:

```powershell
cd D:\Proekt\KeeneticManager
.\.venv\Scripts\Activate.ps1
python main.py
```

## Рабочие данные

Исходный код не используется как хранилище пользовательских данных. На
Windows база роутеров, журналы и диагностическая история находятся в:

```text
%LOCALAPPDATA%\KeeneticManager
```

При первом запуске существующая `database\routers.db` безопасно копируется в
новое расположение и не перезаписывает уже перенесённую базу. Пароли роутеров
хранятся через системное хранилище учётных данных (`keyring`).

Для переносимой или тестовой установки каталог можно задать до запуска:

```powershell
$env:KEENETIC_MANAGER_DATA_DIR = "D:\KeeneticManagerData"
python main.py
```

## Офлайн-анализ прошивок

В разделе «Настройки» включите режим разработчика и нажмите
«Анализировать файл прошивки». Анализатор работает только с локальным файлом:
определяет uImage/FIT, внутреннюю модель Keenetic, архитектуру, версию,
SquashFS, SHA-256, контрольные суммы контейнера, признаки портирования и
предварительный профиль возможностей по найденным RCI-признакам.

Кнопка «Сравнить две прошивки» последовательно предлагает выбрать два файла и
показывает различия моделей, архитектур, версий, целостности и режимов Wi-Fi.
Отчёт анализа или сравнения можно скопировать либо сохранить в TXT.

При активном подключении доступна кнопка «Проверить прошивку для выбранного
роутера». Она сопоставляет внутренний код `KN-xxxx`, текущую и выбранную версии,
целостность, происхождение и предполагаемый режим Wi-Fi. Файл при этом остаётся
локальным и не передаётся устройству.

Каждый завершённый анализ, сравнение или проверка автоматически обновляет
локальный каталог прошивок. Кнопка «Открыть каталог прошивок» позволяет искать
записи, повторно открывать отчёты, сравнивать две сохранённые записи и удалять
метаданные. Каталог находится в пользовательском каталоге `cache`; BIN-файлы в
него не копируются и при очистке каталога не удаляются.

В каталоге можно выбрать сразу несколько BIN-файлов для фонового анализа,
повторно проверить существующий файл или восстановить путь после перемещения.
Новый путь принимается только после полного совпадения SHA-256; неподходящий
файл не изменяет сохранённую запись.

Экспорт JSON переносит выбранные записи или весь каталог без локальных путей и
имён роутеров. Импорт проверяет формат и версию схемы, объединяет записи по
SHA-256 и помечает внешние данные как импортированные до повторной проверки.
Диагностический архив содержит только обезличенный
`firmware_catalog_summary.json`; BIN-файлы и пути в него не включаются.

Файл не изменяется, не отправляется на роутер и не устанавливается. Результат
не является подтверждением совместимости прошивки с конкретным устройством.
Отсутствие статической RCI-строки также не считается доказательством отсутствия
функции: окончательный профиль определяется при подключении к роутеру.

## Самопроверка роутера

Для подключённого роутера в разделе «Настройки → Совместимость роутера»
доступна кнопка «Запустить самопроверку». Она не изменяет конфигурацию и
последовательно проверяет:

- активную сессию мониторинга;
- локальное подключение строго по HTTP и KeenDNS строго по HTTPS;
- авторизацию и чтение безопасного `show/version` через каждый канал;
- полный контрольный цикл обновления, системные данные, Интернет, клиентов,
  Wi-Fi и физические порты;
- профиль поддерживаемых функций и чтение системного журнала.

Медленные запросы отмечаются отдельно. Для каждого роутера хранятся последние
десять результатов, новый отчёт сравнивается с предыдущим, а новые и
устранённые проблемы выделяются в таблице. Кнопка «Повторить проблемные»
запускает только необходимые read-only проверки.

Результат можно скопировать или сохранить в обезличенный JSON без адресов,
имени роутера и учётных данных. Последняя сводка и история автоматически
добавляются в диагностический архив как `router_self_check_summary.json` и
`router_self_check_history.json`.

## Проверка проекта

```powershell
python -m pip install -r requirements-dev.txt
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\quality_check.ps1
```

Проверка компилирует Python-файлы, запускает Ruff, полный комплект тестов и
контролирует минимальное покрытие. Сборщики патча и выпуска запускают её
автоматически; отключать проверку следует только после уже успешного прогона.

## Сборка патча

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\build_patch.ps1
```

Сборщик включает полный согласованный набор исходников, тестов и документации,
а установщик проверяет SHA-256 каждого файла, создаёт резервную копию и запускает
полный комплект тестов перед подтверждением установки.

## Сборка Windows-приложения

```powershell
python -m pip install -r requirements.txt -r requirements-build.txt
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\build_release.ps1
```

Сценарий создаёт самостоятельное Windows-приложение через PyInstaller,
переносимый ZIP и, при наличии Inno Setup 6, полноценный установщик.

## Чистый бекап исходников

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\build_clean_backup.ps1
```

Команда создаёт рядом с проектом папку и ZIP с версией и временем в имени.
Пользовательская база, пароли, журналы, диагностика, кэши и виртуальные
окружения в такой бекап не включаются.
